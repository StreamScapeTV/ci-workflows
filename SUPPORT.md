# Support for ci-workflows

## Where to ask

- **Bug or regression:** [open a bug report](https://github.com/StreamScapeTV/ci-workflows/issues/new/choose) with the affected current source, intended behavior, sanitized reproduction and relevant workflow/operation. Do not attach private CI logs or credentials.
- **Feature or simplification request:** [open a feature request](https://github.com/StreamScapeTV/ci-workflows/issues/new/choose) and explain the current consumer, trust boundary and why existing generic Repository CI cannot handle it. Use [#1076](https://github.com/StreamScapeTV/ci-workflows/issues/1076) for the established workflow-graph reduction roadmap.
- **Contributor setup:** Read [CONTRIBUTING.md](CONTRIBUTING.md) and the [Repository CI guide](docs/repository-ci.md). Where GitHub Discussions is enabled, it can be used for general questions.
- **Security concern:** Follow [SECURITY.md](SECURITY.md); don't submit vulnerabilities or sensitive data as public support requests.

## Expectations

This is a reusable source project, not an on-demand hosted CI or support service. Some workflows require organization-controlled Agent State, macOS hardware, private network access and configured credentials. Outside contributors are not expected to possess these. Maintainer help is best-effort; there is no guaranteed response time, support subscription, or access entitlement.

When reporting a problem, include only reproducible public source behavior and nonsensitive status summaries. Exact source commits and public self-check links are useful; raw private artifacts are not.
